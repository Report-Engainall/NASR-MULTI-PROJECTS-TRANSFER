## 3. نتائج فهرس ZIP الأولية

### ملف الحزمة الصغيرة

الملف AGHBARI_COMMERCE_UNIFIED_SOURCE_PACKAGE (1).zip يحتوي على 19 مدخلًا في فهرس ZIP وحجم إجمالي غير مضغوط مسجل قدره 72,166 بايت. يتضمن README والجرد وبصمات ملفات وسجل مصادر ومواصفات وتعارضات. يحتوي على المسار 02_CANONICAL_PROJECT/NOT_MATERIALIZED.txt الذي يوضح أن شجرة التطبيق لم تُضمّن. بصمة SHA-256 المحسوبة تطابق القيمة الموثقة سابقًا: b5c70093fe28e46b3ebee8394c7bd6bdddf5aef33eb95331e086de4db0790323.

إذن هذا الملف **ليس** بديلًا مثبتًا للأرشيف الأصلي الذي أُبلغ أن حجمه 95,377,100 بايت.

### الملفات SOURCE.1.zip وSOURCE3.zip وSOURCE5.zip

تمت قراءة فهرس ZIP لكل ملف عبر البايتات المستلمة. لكل واحد:
- 282 مدخلًا في الفهرس، تشمل مجلدات.
- حجم غير مضغوط مسجل 2,256,950 بايت.
- جذع مشروع ظاهر باسم project/.
- مسارات وأحجام وCRC-32 مطابقة بين المدخلات المقابلة في الفهارس الثلاثة.

لكن SHA-256 للأرشيفات نفسها مختلف. النتيجة الدقيقة: **مرشحات تكرار قوية على مستوى محتويات الملفات المفهرسة**، وليست أرشيفات متطابقة بايتًا ببايت. يلزم الفك إلى مجلدات معزولة ثم حساب SHA-256 لكل عضو قبل تقرير أن الملفات الداخلية متطابقة.

أسماء المسارات المفهرسة تشمل:
- project/src/ ومكونات وصفحات الواجهة.
- project/drizzle/migrations/ وملفات SQL.
- project/supabase/migrations/.
- project/supabase/functions/ai-gateway/.
- project/supabase/functions/outbox-worker/.
- project/.github/workflows/commerce-checks.yml.
- ملفات الحزم والإعدادات وREADME وAGENTS.md وPROJECT_MEMORY.md.

الأعداد المستخرجة من فهرس الملفات لهذه النسخ: 123 ملف TSX، و48 ملف TS، و40 ملف SQL، و14 ملف Markdown، و8 ملفات JSON، وملفا JS وثلاثة ملفات CSS. هذه **أعداد فهرسية وليست تأكيدًا على البناء أو الاختبارات**.

### تنبيه أمني

## 6. المهمة المطلوبة من Bolt أو بيئة تشغيل مناسبة

1. استخدم نسخة عمل مؤقتة أو GitHub Actions/runner لديه تنزيل بايتات GitHub الخام. نزّل الأرشيفات بأسمائها ومساراتها الأصلية؛ احسب SHA-256 الحقيقي لكل ملف.
2. افحص ZIP باختبار CRC، واستعمل أداة RAR5 حديثة مثل 7zz أو unar لقائمة المحتويات واختبار سلامة RAR وفكّه. اختبر SOURCE12.part1.rar مع SOURCE12.part2.rar كمجموعة واحدة إن أكد تنسيق الأرشيف ذلك.
3. ضع كل أرشيف في مجلد استخراج مستقل. حدّد حدودًا للأعضاء وحجم فك الضغط وعمق الأرشيف، وامنع المسارات المطلقة و.. والروابط الخطرة وzip bombs. لا تنفذ scripts أو migrations أو ملفات تنفيذية مستخرجة.
4. احفظ ARCHIVE_MANIFEST.csv وARCHIVE_MEMBERS.csv مع اسم الأرشيف والمسار والحجم وSHA-256 والنوع وحالة الإدراج أو الاستبعاد وسببها. أضف PROJECT_ROOTS.md لتسمية المشاريع كما ظهرت فعليًا داخل الأرشيف.
5. قارن SHA-256 لأعضاء الملفات بعد الفك، ثم قارن المشاريع مع Nasr1 وREADY_TO_REUSE/PROVENANCE_MANIFEST.csv. سجّل الاختلافات بدل الحذف أو الاستبدال.
6. صنّف كل ملف: مطابق، نسخة أحدث، أكثر اكتمالًا، فرق مفيد، يحتاج تكييفًا، حساس/مستبعد، غير متوافق، أو لم يُفحص.
7. وثّق INTEGRATION_DECISIONS.md وSOURCE_DIFFS.md وDEPENDENCY_SECURITY_REVIEW.md؛ اربط كل قرار بالمصدر والمسار والبصمة والتبعية والاختبار.
8. حدّث missing_inputs.csv وexternal_archive_inventory.csv وexternal_archive_members.csv وpackage-result.json بعد استكمال الفحص، وليس قبله.
9. لا تعلن أن الأرشيفات فُحصت أو المشاريع السبعة استُخرجت حتى تسلّم أدلة البايتات والفك والجرد الفعلي. إذا تعذر مصدر بعينه، سجّله BLOCKED وواصل العمل على المصادر المتاحة.
