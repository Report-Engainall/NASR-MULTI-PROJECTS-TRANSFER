## ثوابت حاكمة

1. الهدف البرمجي هو Report-Engainall/Nasr1 فقط. لا تنتقل إلى Report-Advisor أو مستودع استقبال الأرشيفات.
2. استكمل التطبيق الموجود؛ لا تُعد بناءه من الصفر، ولا تنشئ متجرًا أو قاعدة بيانات أو Supabase project موازيًا.

4. حافظ على ألوان Nasr1 الحالية وشعاره وخطوطه ومكونات التصميم والتنقل وRTL في جميع الشاشات القديمة والجديدة.
5. لا تحذف عملًا سابقًا ولا تدمج كودًا أو SQL أو migrations بصورة عمياء. احتفظ بالمصدر والبصمة والاختلافات، واختبر كل تغيير.
6. كل عنصر مرجعي مفيد، مهما كان صغيرًا، يجب مراجعته وتسجيل قرار بشأنه؛ لا تهمل helpers أو tests أو validators أو retry/idempotency أو SQL/RLS أو التوثيق الأمني لأنها تقلل الجهد والأخطاء.
7. المتطلبات والقيود ثابتة، لكن طريقة التنفيذ ليست جامدة. اختر الحل الهندسي الأفضل إذا كان أكثر أمانًا، وأقل تكرارًا وتعقيدًا وتكلفة، ويحقق المتطلبات نفسها أو أفضل. وثّق السبب والدليل.
8. لا تعلن PASS أو اكتمال المنتج من وجود صفحة أو route أو migration أو build فقط. اربط كل ادعاء بنتيجة اختبار أو دليل تشغيل فعلي.

## المرحلة 2 — جرد كل عناصر READY_TO_REUSE دون إهمال الصغير

بعد مزامنة الوثائق والمجلد المرجعي:

1. افتح PROVENANCE_MANIFEST.csv وراجع كل صف وكل ملف فعلي يقابله.
2. افحص ما إذا كانت الوظيفة موجودة في Nasr1 بالفعل، وما إذا كانت مكتملة أو جزئية، ثم افحص imports والتبعيات والعقود والخدمات والاختبارات.
3. أنشئ/حدّث SOURCE_INTEGRATION_LEDGER.csv وسجّل لكل عنصر المصدر والمستودع والفرع وcommit/blob SHA والمسار الأصلي والبصمة المتاحة والمسار المقابل في الهدف والقرار وسببه والتبعيات والاختبار والحالة.
4. اختر قرارًا واضحًا لكل مادة: ALREADY_PRESENT_EXACT، ALREADY_PRESENT_BETTER، INTEGRATE_AS_IS، ADAPT_AND_INTEGRATE، COMPLETE_EXISTING، KEEP_AS_REFERENCE، DUPLICATE_PROVEN، EXCLUDED_SECURITY، INCOMPATIBLE_WITH_EVIDENCE، أو BLOCKED.
5. لا تضع NOT NEEDED أو DUPLICATE بلا دليل يحدد مكان النسخة الأفضل أو سبب عدم الملاءمة. يجب أن يكون عدد قرارات السجل مساويًا لعدد عناصر manifest التي تمت مراجعتها؛ لا تترك صفوفًا بلا قرار.
6. راجع كل الاختبارات والوثائق الأمنية وSQL والـ helpers. الملفات الصغيرة غالبًا تحفظ نقاطًا ثمينة وتمنع إعادة البرمجة؛ لا تسقط أي عنصر بسبب حجمه أو لأنه ليس واجهة مرئية.
7. عند وجود منطق جزئي في Nasr1، أكمله في المسار الأساسي. عند وجود منطق جيد مع اختلاف contract أو router، حافظ على المنطق والاختبارات وكيّف طبقة الربط بدل إعادة كتابته.
8. ملفات SQL والمهاجرات وEdge Functions المانحة ليست تصريحًا بتطبيقها على قاعدة التشغيل؛ افحص schema وRLS وgrants وRPC وsearch_path والترتيب والتراجع أولًا.

راجع صراحة: unified-import، csvImportPipeline، sha256File، import profiles وimportExcel واختباراتها؛ catalog/pricing/cart/orders/customers/inventory/finance؛ عناوين العملاء وعضويات الشركات والدعوات؛ PDF والمالية والتقريب؛ Onyx Pro الموجود؛ outbox/retry/idempotency والتعافي والتزامن؛ RLS وSQL وعقود الخدمات؛ المكونات والصفحات المرجعية.

وجود 69 مادة تحت docs لا يعني أنها مدمجة. الدمج هو استخدام فعلي متصل بالكود الحي مع اختبارات، أو قرار موثق للاحتفاظ بالمادة مرجعًا فقط.

## المرحلة 3 — فحص الأرشيفات الحقيقية دون ادعاء

التقرير ARCHIVE_INTAKE_RECONCILIATION_2026-10-17.md يسجل 12 ملف أرشيف بإجمالي 90,825,000 بايت: 7 ZIP و5 RAR/أجزاء RAR. الملفات SOURCE.1.zip وSOURCE3.zip وSOURCE5.zip مرشحات تكرار قوية من فهارسها؛ لكن بصمات الأرشيفات مختلفة، فلا تستبعدها نهائيًا إلا بعد مقارنة بصمات الملفات بعد فكها.

1. افحص المسار الحي أولًا ولا تطلب إعادة رفع ما هو موجود بالفعل.
2. استخدم بيئة Bolt أو GitHub Actions/runner مجانيًا ومتاحًا يمكنه تنزيل بايتات الملفات الثنائية. حساب الحجم أو قراءة اسم الملف لا يثبت استخراجًا.
3. احسب SHA-256 الحقيقي لكل أرشيف؛ لا تساوِ Git blob SHA مع SHA-256.
4. اختبر ZIP CRC ثم فك كل ملف في مجلد منفصل. استخدم أداة مجانية حديثة تدعم RAR5 مثل 7zz أو unar. اختبر SOURCE12.part1.rar وSOURCE12.part2.rar معًا إذا أكد التنسيق أنها أجزاء أرشيف واحد.
5. ضع حدودًا لحجم فك الضغط وعدد الأعضاء والعمق، وامنع path traversal والمسارات المطلقة والروابط الخطرة وzip bombs. لا تشغّل الكود المستخرج.
6. يظهر اسم project/.env في فهرس بعض ZIPs. لا تطبع محتواه أو أسراره ولا تنشره. افحصه محليًا بأمان واستبعده أو نقّح الأسرار والمفاتيح والبيانات الحساسة في المخرجات.
7. أنشئ manifest للأرشيفات وجردًا لكل عضو يشمل المسار والحجم وSHA-256 والنوع والحالة والسبب، وحدد جذور المشاريع من المحتويات التي تم فكها فعلًا.
8. قارن كل ملف مستخرج مع Nasr1 وكل READY_TO_REUSE. حافظ على النسخ المختلفة وسجّل أحدث/أكمل/مفيد/غير متوافق/حساس/محجوب مع الدليل.
9. لا تعتبر الأرشيف الأصلي AGHBARI_COMMERCE_UNIFIED_SOURCE_PACKAGE.zip بحجم 95,377,100 بايت موجودًا لمجرد تشابه الاسم. ولا تعتبر RAR المشاريع السبعة في adnanabderab2016-sys/-7- المستند إلى Git blob dd96610641b7f0a7af765b72d406b1553f67f89e مستخرجًا؛ ما يزال يحتاج تنزيل بايتاته وSHA-256 واختبارًا واستخراجًا مثبتًا.
10. الأرشيف الإضافي متعدد المشاريع يجب البحث عنه في الملفات وReleases المتاحة قبل طلب رفع جديد. إن بقي ملف محجوبًا، سجّله BLOCKED بدليل وواصل بقية العمل بدل توقف المشروع.

## المرحلة 5 — التكلفة والهوية البصرية والاختبارات

### شرط التكلفة: صفر دفع جديد

- افحص package.json وlockfiles والإصدارات والتقنيات الموجودة قبل تثبيت أي شيء.

- لا ترفع خطط الاستضافة ولا تشغّل موارد مدفوعة إضافية دون موافقة المالك.

### الهوية البصرية

احفظ commits صغيرة بعد كل مجموعة مستقرة؛ لا تنتظر أن يطلب المالك الحفظ أو تذكيرك بالاستمرار.

التقرير النهائي يجب أن يذكر:
1. المستودع والفرع وHEAD الفعلي.
2. عدد صفوف manifest التي تمت مراجعتها والقرارات لكل العناصر دون إسقاط أي صف.
3. الأرشيفات التي نُزّلت واختُبرت وفُكّت فعلًا، وعدد المشاريع والملفات بعد الاستخراج وSHA-256؛ والمفقودات BLOCKED.
4. الملفات الجديدة والمتطابقة والأحدث والمكيّفة والمستبعدة وأسباب الاستبعاد.
5. الوحدات والشاشات التي دُمجت فعليًا مع المسارات والاختبارات.
6. حالة جميع نطاقات لوحة التحكم حسب الدليل.
7. نتائج كل اختبار شُغّل بالفعل، بما فيها الفشل.
8. بيان الاعتماديات الجديدة وتراخيصها ودليل عدم إضافة تكلفة إلزامية.
9. آخر commit وملف الاستئناف والخطوة التالية.

## أمر التنفيذ المختصر

زامن أولًا ملفات المرحلة 1 إلى مساحة عمل Bolt وتحقق من وجودها. راجع كل صف وملف في READY_TO_REUSE، بما في ذلك المواد الصغيرة، وسجّل قرارًا بدليل لكل عنصر. افحص الأرشيفات الأصلية الحقيقية وبصماتها بأدوات مجانية وآمنة، ولا تدّع استخراج ما لم يحدث. ادمج أفضل الأكواد التي ثبت نفعها داخل Nasr1 دون تكرار أو حذف، ثم أكمل لوحة التحكم وكل المتطلبات الناقصة، مع الحفاظ على ألوان Nasr1 ومنع أي تقنية تفرض دفعًا جديدًا. اختبر وأصلح واحفظ commits وسجل استئناف مستمر.
